## Overview
When you call a function with arguments, C++ gives you three distinct ways to pass that data: **by value**, **by reference**, **by pointer**. Each has different performance characteristics and different effects on the original data - choosing the right one is a core C++ skill.

## 1. Pass by Value
A **copy** of the argument is made and given to the function. Changes inside the function do **not** affect the original variable.

```cpp
void increment(int n) {
    n = n + 1;
    std::cout << "Inside function: " << n << std::endl;
}

int main() {
    int x = 5;
    increment(x);
    std::cout << "Outside function: " << x << std::endl;  // Still 5
    return 0;
}

/* Output:
Inside function: 6
Outside function: 5
*/
```

> [!WARNING]
> Pass by value is safe but can be expensive for large objects (like a big `std::string` or `struct`) because the **entire object is copied** every single call.

## 2. Pass by Reference
A **reference** (an alias to the original variable's memory) is passed instead of a copy. Changes inside the function **directly affect** the original variable.

```cpp
void increment(int& n) {
    n = n + 1;
}

int main() {
    int x = 5;
    increment(x);
    std::cout << "x is now: " << x << std::endl;     // 6
    return 0;
}
```

* The `&` after the type marks it as a reference parameter.
* No copy is made - references operate directly on the original memory.

> [!TIP]
> Pass by reference is significantly faster than pass by value for large objects since no copy occurs. It is the standard choice when a function needs to modify the caller's variable, or when passing large data that shouldn't be copied.

## 3. Pass by Const Reference
When you want the **performance benefit** of reference (no copying) but want to **prevent modification** of the original - the best of both worlds for read-only access to large data.

```cpp
void printName(const std::string& name) {
    std::cout << "Name: " << name << std::endl;
    // name = "Changed";   // ERROR: cannot modify a const reference
}
```

> [!IMPORTANT]
> `const std::string&` is the standard, idiomatic way to pass large read-only objects (strings, vectors, custom classes) into a function in professional C++ code. It avoids unnecessary copying while protecting the caller's data from accidental modification.

## 4. Pass by Pointer
A **pointer** (the memory address of the variable) is passed. The function can modify the original value by dereferencing the pointer.

```cpp
void increment(int* n) {
    *n = *n + 1;  // dereferencing to access/modify the actual value
}

int main() {
    int x = 5;
    increment(&x);      // pass the address of x
    std::cout << "x is now: " << x << std::endl;   // 6
    return 0;
}
```

 * `&x` → "address of x" — gets a pointer to `x`.
 * `*n` → "dereference n" — accesses the value n is pointing to.

## Reference vs Pointer - When to Use Which
| Aspect                 | Reference(`&`)                     | Pointer (`*`)                         |
| ---------------------- | ---------------------------------- | ------------------------------------- |
| Can be Null?           | No, must always refer to something | Yes, can be `nullptr`                 |
| Can be reassigned?     | No, bound at initialization        | Yes, can point elsewhere later       |
| Syntax at call site    | Clean - `func(x)`                  | Requires `&` - `func(&x)`             |
| Syntax inside function | Direct - `n`                       | Required dereference - `*n`           |
| Common use case        | Default choice for most parameters | When "no value" / optionality matters |

> [!NOTE]
>As a general rule: prefer references for required parameters, and pointers only when a parameter might legitimately need to be "nothing" (`nullptr`), or for compatibility with C-style APIs.

## Returning Values from Functions
Parameters decide how data goes **in**; the return type decides how it comes **out**.

### Return by Value (the Default)

```cpp
std::string makeGreeting() {
    return "Hello";
}

std::string msg = makeGreeting();
```

> [!NOTE]
> Returning by value is usually cheap, even for large types like `std::string`. The compiler applies **copy elision**: the returned object is constructed directly in the caller's variable instead of being copied. This is guaranteed when returning a temporary (C++17) and commonly applied to named locals. Do not "optimize" by returning pointers or references to locals.

### Return by Reference
Return a reference when the caller should get access to an **existing** object rather than a copy. The caller can then even assign through it:

```cpp
int& elementAt(int* arr, int index) {
    return arr[index];
}

int data[3] = {1, 2, 3};
elementAt(data, 1) = 99; // modifies the real element: data is now {1, 99, 3}
```

The referenced object must **outlive the call**. Safe targets are the caller's variables passed in by reference, globals, `static` variables, heap objects, and class members.

### Never Return a Reference or Pointer to a Local

```cpp
int& bad() {
    int x = 5;
    return x; // x is destroyed when the function returns
}

// the caller receives a dangling reference -> undefined behavior
```

GCC reports `warning: reference to local variable 'x' returned [-Wreturn-local-addr]`. The same applies to returning the address of a local through a pointer.

### Returning a Reference to a Parameter

```cpp
const std::string& longer(const std::string& a, const std::string& b) {
    return (a.size() >= b.size()) ? a : b;
}

std::string x = "ab", y = "abc";
std::cout << longer(x, y) << "\n"; // x and y outlive the call
const std::string& r = longer(std::string("ab"), std::string("abc"));     // DANGLING: temporaries expire here
std::cout << r << "\n"; // undefined behavior
```

> [!WARNING]
> A function that returns a reference to one of its reference parameters is only safe if the arguments outlive the result. Passing temporaries (see below) breaks that, so be careful with this pattern.

### Which Parameters Accept Temporaries?
A **temporary** is an unnamed value such as `makeGreeting()` or the literal `"text"`.

| Parameter type    | Accepts a variable?  | Accepts a temporary? |
| ----------------- | -------------------- | -------------------- |
| `std::string`          | Yes (copies it)      | Yes                  |
| `std::string&`         | Yes                  | **No**               |
| `const std::string&`   | Yes                  | Yes                  |

```cpp
void print(const std::string& s) { std::cout << s << "\n"; }
void modify(std::string& s) { s += "!"; }

print("temporary");
modify(makeGreeting()); // ERROR: non-const references cannot bind to temporaries
```

A non-`const` reference promises to modify an object the caller can see, which is meaningless for a temporary that vanishes immediately. That is why `const&` is the standard way to accept "any string, read-only".

Binding a temporary to a **local** `const` reference extends its lifetime to the reference's scope:

```cpp
const std::string& r = makeGreeting(); // the temporary lives as long as r
std::cout << r << "\n";   // Hello
```

> [!TIP]
> A function returns one value. To return several, prefer returning a `struct` (covered in 4.4) or `std::pair` / `std::tuple` (STL). Reference "output parameters" (`void f(int& out)`) work, but they make call sites harder to read.

> [!TIP]
> The standard library already provides the swap function you wrote with references:
> ```cpp
> #include <utility>
>
> int a = 1, b = 2;
> std::swap(a, b);   // a is 2, b is 1
> ```

## Summary Table

| Passing Method     | Copy Made?          | Can Modify Original? | Use Case                                   |
| ------------------ | ------------------- | -------------------- | ------------------------------------------ |
| By Value           | Yes                 | No                   | Small type (`int`, `char`, `bool`)         |
| By Reference       | No                  | Yes                  | Need to modify the original                |
| By Const Reference | No                  | No                   | Large read-only data (strings, objects)    |
| By Pointer         | No (copies address) | Yes                  | Optional/nullable parameters, C-style code |
