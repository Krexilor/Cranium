## Overview
A **type conversion** turns a value of one type into another. It happens in two ways:
* **Implicit conversion** - the compiler does it automatically, often without any warning.
* **Explicit conversion (a cast)** - you request it in the code, which documents your intent.

Most conversion bugs come from conversions the programmer did not realize were happening.

## Implicit Conversions

```cpp
int i = 42;
double d = i;          // int -> double: safe, value preserved

double avg = 7 / 2;    // 7 / 2 is INTEGER division = 3, then 3 -> 3.0 (avg is 3.0, NOT 3.5)

int n = 3.9;           // double -> int: fractional part DROPPED, n is 3
bool flag = 10;        // any non-zero value -> true, 0 -> false
```

| Kind                      | Meaning                                         | Examples                                           |
| ------------------------- | ----------------------------------------------- | -------------------------------------------------- |
| **Widening**              | Target can hold every source value              | `int` -> `long long`, `float` -> `double`          |
| **Narrowing**             | Target may lose data                            | `double` -> `int`, `long long` -> `int`, `int` -> `char` |

> [!WARNING]
> Narrowing conversions compile silently. `double` -> `int` **truncates toward zero** (`3.9` -> `3`, `-3.9` -> `-3`), and `long long` -> `int` of an out-of-range value changes the number (for example, `3000000000LL` becomes `-1294967296` on a typical 32-bit `int`). A `double` too large for an `int` is **undefined behavior**.

## Integral Promotion & Usual Arithmetic Conversions
Before arithmetic, types smaller than `int` (`char`, `short`, `bool`) are **promoted** to `int`. When the two operands of a binary operator have different types, the compiler converts them to a common type:

| Expression    | Common type used  | Result  |
| ------------- | ----------------- | ------- |
| `'A' + 1`     | `int`             | `66`    |
| `5 + 2.5`     | `double`          | `7.5`   |
| `7 / 2`       | `int`             | `3`     |
| `7 / 2.0`     | `double`          | `3.5`   |

The general rule: if either operand is floating-point, the result is floating-point. Otherwise both are promoted, then the smaller type is converted to the larger one.

### The Signed / Unsigned Trap
When a signed and an unsigned value of the same size meet, the **signed value is converted to unsigned**:

```cpp
unsigned int u = -1;           // wraps around: u is 4294967295 (well-defined)

std::cout << (-1 < 1u) << "\n";     // 0 (false!) -1 becomes 4294967295 before the comparison

int i = -1;
std::size_t n = 3;
if (i < n) { }                 // false, for the same reason
```

> [!IMPORTANT]
> Comparing or mixing signed and unsigned integers is a frequent source of subtle bugs. Keep values that can be negative in signed types, and convert explicitly when you have to mix them.

## C-Style Casts
C++ inherited a cast syntax from C:

```cpp
double d = 3.9;
int a = (int)d;                    // C-style cast
int b = int(d);                    // functional-style cast
int c = static_cast<int>(d);       // C++ named cast (preferred)
```

> [!WARNING]
> A C-style cast silently tries several different conversions, including dangerous ones such as reinterpreting raw memory or removing `const`. It is also hard to search for in a codebase. Prefer **named casts**, which each do one specific thing and are easy to find.

## `static_cast`
`static_cast<TargetType>(expression)` is the everyday cast. It performs conversions between **related types** and is checked at compile time.

```cpp
int a = 7, b = 2;

std::cout << a / b << "\n";                         // 3   (integer division)
std::cout << static_cast<double>(a) / b << "\n";    // 3.5 (a becomes a double first)
std::cout << static_cast<double>(a / b) << "\n";    // 3; division happened before the cast
```

> [!WARNING]
> **Cast the operand, not the result.** `static_cast<double>(a) / b` converts first and divides in floating-point. `static_cast<double>(a / b)` divides as integers first and only then converts the already-truncated answer.

```cpp
double x = 3.9, y = -3.9;
int t1 = static_cast<int>(x);        // 3   (truncates toward zero)
int t2 = static_cast<int>(y);        // -3  (NOT -4)
// Use round(), floor() or ceil() from <cmath> when you want rounding instead

char c = 'A';
std::cout << static_cast<int>(c) << "\n";         // 65
std::cout << static_cast<char>(66) << "\n";       // B
```

`static_cast` refuses nonsensical conversions, which is its main safety benefit:

```cpp
int n = static_cast<int>("42");     // COMPILE ERROR: a string literal is not a number
```

Other uses of `static_cast` appear later: converting `void*` back to a typed pointer, and moving up or down a class hierarchy.

## Brace Initialization & Narrowing

```cpp
int x{3.5};                          // ERROR: narrowing conversion, the compiler must diagnose it
int y = 3.5;                         // compiles, y is 3 (silent truncation)
int z{ static_cast<int>(3.5) };      // OK: the narrowing is explicit
```

## Converting Between Strings and Numbers
Casts do **not** convert text to numbers. Use library functions from `<string>`:

```cpp
#include <std::string>

std::string s = to_string(42) + "!";      // "42!"      number -> string
int n = stoi("123");                 // 123        string -> int
double d = stod("2.5");              // 2.5        string -> double
```

> [!WARNING]
> `stoi("42abc")` quietly returns `42` and ignores the rest, while `stoi("abc")` throws an exception (`invalid_argument`). Exceptions are covered in a later topic, so for now validate input with `std::cin` as shown in 2.3.

## The Four Named Casts
C++ has four named casts. Only `static_cast` is needed at this stage; the others are previewed here and covered where their prerequisites are introduced.

| Cast               | Purpose                                                      | Risk                                                     | Covered in                          |
| ------------------ | ------------------------------------------------------------ | -------------------------------------------------------- | ----------------------------------- |
| `static_cast`      | Conversions between related types, checked at compile time   | Low                                                      | **This section**                    |
| `const_cast`       | Add or remove `const` from a pointer or reference            | Modifying an object that was truly `const` is undefined behavior | Pointers (`const` with pointers) |
| `reinterpret_cast` | Reinterpret raw bits or an address as an unrelated type      | Very high; rarely needed                                 | Pointers (`const` with pointers)    |
| `dynamic_cast`     | Safe downcast in a polymorphic class hierarchy, checked **at runtime** | Needs `virtual` functions; fails with `nullptr` (pointers) or an exception (references) | Inheritance & polymorphism |

## Best Practices
* Avoid casts when the code can be restructured so none is needed. A cast is a statement that you know better than the type system.
* Prefer `static_cast` over C-style casts, and never use C-style casts in new code.
* Prefer brace initialization so narrowing is caught at compile time.
* Keep signed and unsigned values separate, and convert explicitly where they meet.
* Cast the operand you want converted, then do the operation.

> [!TIP]
> Many compilers can flag risky implicit conversions. With GCC or Clang, try `-Wall -Wextra -Wconversion -Wsign-compare`. For example, `-Wconversion` reports `conversion from 'double' to 'int' may change value`.
