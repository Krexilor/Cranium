## Overview
A **variable** is a named storage location in memory that holds a value. Every variable in C++ must have a **type** declared at the moment of creation. The type tells the compiler how much memory to allocate and how to interpret the stored bits.

## Fundamental Data Types

| Type        | Description              | Size (typical) | Example Value    |
| ----------- | ------------------------ | -------------- | ---------------- |
| `int`       | Whole numbers            | 4 bytes        | `42`, `-7`       |
| `double`    | Floating-point (decimal) | 8 bytes        | `3.14`, `-0.001` |
| `float`     | Single-precision decimal | 4 bytes        | `3.14f`          |
| `char`      | Single character         | 1 byte         | `'A'`, `'7'`     |
| `bool`      | True or False            | 1 byte         | `true`, `false`  |
| `std::string`    | Sequence of characters   | Dynamic        | `"Hello"`        |
| `long long` | Large while numbers      | 8 bytes        | `987654321`      |

> [!NOTE]
>  Unlike the others, `std::string` is a class from the Standard Library (`#include <string>`). It is included automatically with `<iostream>` in most compilers, but it's good practice to include it explicitly.

## Type Modifiers
Modifiers adjust the range and storage of base types.

| Modifier        | Effect                                                          |
| --------------- | --------------------------------------------------------------- |
| `unsigned int`  | No negative values. Range doubles on positive side              |
| `short int`     | Typically 2 bytes instead of 4                                  |
| `long int`      | At least 4 bytes (4 on 64-bit Windows, 8 on 64-bit Linux/macOS) |
| `long long int` | At least 8 bytes (64 bits). 8 bytes on all mainstream platforms |

> [!NOTE]
> C++ only guarantees *minimum* sizes and the ordering `short <= int <= long <= long long`. Exact sizes depend on the compiler and platform. When an exact size matters, use the fixed-width types introduced below.

```cpp
unsigned int score = 4294967295;      // Max value, no negatives
short int temp = -32000;
long long int bigNumber = 9000000000LL;
```

## Integer Overflow
Every integer type has a fixed range. Exceeding it is **overflow**, and the rules depend on signedness:

| Type                                  | What happens on overflow                  |
| ------------------------------------- | ----------------------------------------- |
| `unsigned` types                      | Well-defined: wraps around (modulo 2ⁿ)    |
| Signed types (`int`, `long long`, …)  | **Undefined behavior**                    |

```cpp
unsigned int u = 4294967295;      // max value of a 32-bit unsigned int
u = u + 1;
std::cout << u << "\n";           // 0 (wrapped around - well-defined)

int i = 2147483647;               // max value of a 32-bit int
i = i + 1;                        // UNDEFINED BEHAVIOR (signed overflow)
```

> [!WARNING]
> Never rely on signed overflow "wrapping around". The compiler is allowed to assume it never happens and may optimize your code based on that assumption (see 2.8). If values might exceed the range, use a wider type (`long long`) or check before the operation.

## Fixed-Width Integer Types
`int` and `long` change size between platforms. `<cstdint>` provides types with an **exact** size.

```cpp
#include <cstdint>

int8_t   a = -100;                // exactly 8 bits, signed
uint8_t  b = 255;                 // exactly 8 bits, unsigned
int32_t  c = 100;                 // exactly 32 bits, signed
uint32_t d = 4000000000U;         // exactly 32 bits, unsigned
int64_t  e = 9000000000;          // exactly 64 bits, signed
uint64_t f = 18000000000000000000ULL;
```

Use them when the exact size matters: binary file formats, network protocols, hardware registers, and bit manipulation. For ordinary counters and arithmetic, plain `int` is fine.

> [!WARNING]
> `int8_t` and `uint8_t` are usually aliases for `char` types, so `std::cout` prints them as **characters**:
> ```cpp
> uint8_t level = 65;
> std::cout << level << "\n";                     // A   (printed as a character!)
> std::cout << +level << "\n";                    // 65  (unary + promotes to int)
> std::cout << static_cast<int>(level) << "\n";   // 65  (clearer - see 2.7)
> ```

## `std::size_t`
`std::size_t` is the unsigned integer type used for **sizes and counts**. It is what `sizeof` returns, and it is the type of container sizes and array indices in the standard library. On a 64-bit system it is 8 bytes.

Because it is unsigned, it has two classic pitfalls:

```cpp
// Pitfall 1: mixing signed and unsigned in a comparison
int i = -1;
std::size_t n = 3;
if (i < n) { }    // FALSE: i is converted to a huge unsigned value (see 2.7)

// Pitfall 2: counting down with an unsigned type never ends
for (std::size_t k = 3; k >= 0; k--) { }  // k >= 0 is ALWAYS true; k wraps to a huge value

// Correct countdown: test, then decrement
for (std::size_t k = 3; k-- > 0; ) {      // visits 2, 1, 0 and stops
    std::cout << k << " ";
}
```

## Querying Type Limits
Do not hard-code limits like `2147483647`. Ask the compiler with `<limits>`:

```cpp
#include <limits>

std::cout << std::numeric_limits<int>::max() << "\n";            // 2147483647
std::cout << std::numeric_limits<int>::min() << "\n";            // -2147483648
std::cout << std::numeric_limits<unsigned int>::max() << "\n";   // 4294967295
std::cout << std::numeric_limits<long long>::max() << "\n";      // 9223372036854775807
std::cout << std::numeric_limits<double>::epsilon() << "\n";     // 2.22045e-16
```

> [!NOTE]
> `std::numeric_limits<T>` works for every fundamental type and adapts to the platform, so it never becomes a magic number (see 2.6). The older C-style equivalents are `INT_MAX` and friends in `<climits>`.

## Floating-Point Precision
`float` holds about 6-7 significant decimal digits and `double` about 15-16. Many decimal fractions, like `0.1`, cannot be represented exactly in binary, so tiny errors appear:

```cpp
#include <iomanip>

double sum = 0.1 + 0.2;
std::cout << setprecision(17) << sum << "\n";     // 0.30000000000000004
std::cout << boolalpha << (sum == 0.3) << "\n";   // false
```

Compare floating-point values with a **tolerance**, never with `==`:

```cpp
#include <cmath>

double epsilon = 1e-9;
if (fabs(sum - 0.3) < epsilon) {
    std::cout << "Close enough\n";                // prints
}
```

> [!IMPORTANT]
> Never test floating-point results for exact equality. Pick a tolerance that suits the magnitude of your values (`std::numeric_limits<double>::epsilon()` is the spacing near 1.0, so scale it for larger or smaller numbers). For money, store whole cents in an integer instead of using `double`.

## `char` Is Also a Number
A `char` is a small integer that happens to be printed as a character (ASCII on virtually all systems: `'0'` = 48, `'A'` = 65, `'a'` = 97). Arithmetic on a `char` produces an `int`.

```cpp
char c = 'A';
std::cout << c + 1 << "\n";                       // 66 ('A' is 65, and c + 1 is an int)
std::cout << static_cast<char>(c + 1) << "\n";    // B (cast the int back to a char)
std::cout << ('7' - '0') << "\n";                 // 7  (digit character -> numeric value)
```

> [!NOTE]
> Whether a plain `char` is signed or unsigned is up to the compiler (see 2.8). Use `char` for characters. For small numbers, use `int` or an explicit `int8_t` / `uint8_t`.

## Math Functions with `<cmath>`

| Function     | Purpose                    | Example             | Result |
| ------------ | -------------------------- | ------------------- | ------ |
| `sqrt(x)`    | Square root                | `sqrt(16.0)`        | `4`    |
| `pow(x, y)`  | x raised to the power y    | `pow(2, 10)`        | `1024` |
| `fabs(x)`    | Absolute value (floating)  | `fabs(-3.2)`        | `3.2`  |
| `floor(x)`   | Round down                 | `floor(-2.5)`       | `-3`   |
| `ceil(x)`    | Round up                   | `ceil(2.1)`         | `3`    |
| `round(x)`   | Round to nearest (.5 away from zero) | `round(2.5)` | `3` |

> [!NOTE]
> These all return `double`. `pow` is a floating-point function, so for large integer powers the result can lose precision. Compute exact integer powers with a loop instead.

## Declaring & Initializing Variables

```cpp
// Declaration (memory reserved, value is garbage/undefined)
int age;

// Initialization (declaration + value assignment)
int age = 25;

// Modern C++11 uniform initialization (preferred)
int age{ 25 };
double price{ 9.99 };
std::string name { "Krexilor" };
```

> [!WARNING]
> **Uninitialized Variables:** Reading an uninitialized variable is **undefined behavior** in C++. It may contain random garbage data from whatever was previously at the memory address. Always initialize your variables.

> [!NOTE]
> **Brace initialization rejects narrowing:** `int x{3.5};` is a compile error because it would silently lose data, while `int x = 3.5;` compiles and quietly truncates to `3`. This is one of the main reasons brace initialization is preferred. Conversions and casts are covered in 2.7.

## `auto` Keyword (C++11)
The `auto` keyword lets the compiler **deduce the type** from the assigned value. Useful when the type is obvious or complex.

```cpp
auto score = 100;                      // deduced as int
auto price = 19.99;                    // deduced as double
auto name = "Krex";                    // deduced as const char* (not string!)

auto fullName = std::string{"Krex"};   // explicitly a string
```

> [!NOTE]
> **When to use auto:** Use `auto` when the type is either obvious from context or very verbose (like iterator types). Avoid it when it obscures what type a variable actually is.

## Constants
A **constant** is a variable whose value cannot be changed after initialization.

### `const` - Read-Only Variables

```cpp
const double PI = 3.14159265;
const int MAX_PLAYERS = 4;

PI = 3.0            // ERROR: cannot modify a const variable
```

### `constexpr` - Compile-Time Constant (C++11)
`constexpr` forces evaluation at **compile time**, making it faster than `const` for values that are truly fixed.

```cpp
constexpr int SCREEN_WIDTH = 1920;
constexpr double GRAVITY = 9.81;
```

> [!NOTE]
> **const vs constexpr:** Use `constexpr` for values known at compiler time (screen sizes, math constants, fixed limits). Use `const` for values that cannot change after initialization but are not necessarily known during compilation (e.g., a user's input stored as a constant). A `const` variable initialized with a constant expression can also be used at compile time, but only `constexpr` guarantees it.

## Naming Convention

```cpp
int playerHealth;                      // camelCase (common for variables)
const int MAX_HEALTH = 100;            // UPPER_SNAKE_CASE (common for constants)
std::string firstName;                 // camelCase
```

Rules enforced by the compiler:
* Must start with a letter or underscore `_`.
* Cannot be a C++ keyword (`int`, `return`, `class`, etc.).
* Case-sensitive (`Score`  ≠ `score`)
