## Overview
A function lives in memory, and so it has an **address**. A **function pointer** stores that address, so that *which function runs* can be decided at runtime and passed around like any other value. It is the basis of **callbacks**, dispatch tables, and C library APIs such as `qsort`.

## Declaring and Using a Function Pointer

```cpp
int add(int a, int b)      { return a + b; }
int subtract(int a, int b) { return a - b; }

int(*op)(int, int) = add;             // op points to a function taking (int, int) and returning int

std::cout << op(3, 4) << "\n";              // 7
std::cout << (*op)(3, 4) << "\n";           // 7 (the explicit dereference is optional)

op = &subtract;                        // & is optional too: a function name converts to a pointer
std::cout << op(10, 4) << "\n";             // 6
```

Reading `int (*op)(int, int)`: `op` is a pointer (`*op`) to a function that takes `(int, int)` and returns `int`.

> [!WARNING]
> The parentheses around `*op` are essential. `int *op(int, int)` declares an ordinary **function named `op` returning `int*`**, which is a completely different thing (and produces a confusing error when you try to initialize it).

The pointer's type must match the function's signature **exactly** (return type and parameter types):

```cpp
double(*p)(double, double) = add;
// ERROR: invalid conversion from 'int(*)(int, int)' to 'double(*)(double, double)'
```

`auto` removes the syntax burden: `auto f = add;` deduces `int (*)(int, int)`.

## Type Aliases Make It Readable

```cpp
using BinaryOp = int(*)(int, int);    // BinaryOp = "pointer to a function(int, int) -> int"

BinaryOp op = add;
```

(Aliases are covered in 4.4.) Always prefer an alias once function pointers appear in parameters, return types, or arrays.

## Function Pointers as Parameters (Callbacks)
The caller chooses the behavior, and the function just invokes it:

```cpp
int multiply(int a, int b) { return a * b; }

int apply(int a, int b, BinaryOp op) {
    return op(a, b);
}

std::cout << apply(6, 7, multiply) << "\n";     // 42
std::cout << apply(6, 7, add) << "\n";          // 13
```

## Arrays of Function Pointers (Dispatch Tables)

```cpp
BinaryOp table[3] = {add, subtract, multiply};

for (int i = 0; i < 3; i++) {
    std::cout << table[i](8, 2) << " ";         // 10 6 16
}
```

## Returning a Function Pointer

```cpp
BinaryOp pick(char symbol) {
    switch (symbol) {
        case '+': return add;
        case '-': return subtract;
        case '*': return multiply;
        default:  return nullptr;          // no such operation
    }
}

BinaryOp chosen = pick('*');
if (chosen != nullptr) {                   // always check before calling
    std::cout << chosen(4, 5) << "\n";          // 20
}
```

> [!WARNING]
> Calling a `nullptr` function pointer is undefined behavior, exactly like dereferencing any null pointer (5.3). Check before you call.

## Real Example: `qsort`
The C library's sort function in `<cstdlib>` takes a comparison function because it cannot know your element type. This is where `void*` (5.1) and function pointers meet:

```cpp
#include <cstdlib>

int compareInts(const void* a, const void* b) {
    int x = *static_cast<const int*>(a);       // recover the real type (see 5.1)
    int y = *static_cast<const int*>(b);
    return (x > y) - (x < y);                  // negative, zero, or positive
}

int nums[5] = {42, 7, 19, 3, 88};
qsort(nums, 5, sizeof(int), compareInts);      // nums is now {3, 7, 19, 42, 88}
```

The comparator must return a negative number if the first element comes first, `0` if they are equal, and a positive number otherwise. `(x > y) - (x < y)` is used instead of `x - y`, because the subtraction can overflow (undefined behavior for signed integers, 2.8).

> [!NOTE]
> In C++ you will normally use `std::sort` instead, which is type-safe and faster. It takes a comparison callable (lambda or functor) and is covered with the STL algorithms.

## Overloaded Functions
When a function name is overloaded (3.3), the pointer's type selects the overload:

```cpp
int    twice(int v)    { return v * 2; }
double twice(double v) { return v * 2; }

int(*p1)(int)       = twice;              // picks the int version
double(*p2)(double) = twice;              // picks the double version

std::cout << p1(4) << " " << p2(1.5) << "\n";   // 8 3

// auto p = twice;                         // ERROR: unable to deduce 'auto' from 'twice'
```

## Limitations
* A function pointer holds **only an address**: no state, no captured variables. Lambdas and `std::function` (Topic 11) can carry state, and are preferred for callbacks in modern C++.
* Pointers to **member functions** of classes have a different type and syntax (Topic 6).
* The pointer is a normal pointer-sized object (`sizeof` is 8 on a 64-bit system).
