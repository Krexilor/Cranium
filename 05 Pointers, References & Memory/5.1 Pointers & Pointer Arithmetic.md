## Overview
A **pointer** is a variable that stores the **memory address** of another variable rather than a value itself. Pointers are arguably the most powerful - and most dangerous - feature of C++. They underlie dynamic memory, arrays, data structures, and hardware-level programming.

## Memory Addresses
Every variable you declare occupies a location in memory identified by an **address** - a unique numeric value representing its position in RAM.

```cpp
int x = 42;
std::cout << x << std::endl;     // prints the value: 42
std::cout << &x << std::endl;    // prints the address: e.g., 0x7ffd3b2a1c4
```

* The `&` operator here is the **address-of operator** - it retrieves the memory address of a variable.

## Declaring a Pointer
A pointer is declared using `*` after the type. The type specifies what kind of data the pointer *points to*.

```cpp
int* ptr;          // pointer to an int
double* dptr;      // pointer to a double
char* cptr;        // pointer to a char
```

> [!NOTE]
> The `*` placement is a style choice - `int* ptr`, `int *ptr`, and `int * ptr` are all valid. Many C++ developers prefer `int* ptr` (star with the type) to emphasize that `ptr` is of type "pointer to int."

## Assigning & Using Pointers

```cpp
int x = 42;
int* ptr = &x;           // ptr now holds the address of x

std::cout << ptr << std::endl;     // address
std::cout << *ptr << std::endl;    // 42 - dereference: access the value AT that address
```

* `&x` → **address-of** - gets the address of `x`.
* `*ptr` → **dereference** - follows the pointer to access the value it points to.

> [!TIP]
> A helpful mental model: a pointer is like a house address written on a piece of paper. The paper (`ptr`) holds the address. Going to that address and looking inside is dereferencing (`*ptr`). The address-of operator (`&x`) is like looking up a house's address to write down.

## Modifying Values Through Pointers
Since dereferencing gives you direct access to the original variable's memory, you can modify the original value through the pointer.

```cpp
int x = 42;
int* ptr = &x;

*ptr = 100;          // modifies x through the pointer
std::cout << x << std::endl;   // 100 - x itself has changed
```

This is the foundation of **pass by pointer** in functions - you pass an address and modify the original variable without returning a new value.

## Pointer to Pointer
A pointer can point to another pointer, adding another layer of indirection.

```cpp
int x = 42;
int* ptr = &x;
int** pptr = &ptr;         // pointer to a pointer to int

std::cout << **pptr << std::endl;    // 42 - double dereference to get the value
std::cout << *pptr << std::endl;     // address of x (same as ptr)
```

> [!NOTE]
> Double pointers (`**`) become important when dealing with 2D dynamic arrays, or when a function needs to modify a pointer itself (not just the value it points to).

## Pointer Arithmetic
Because arrays are stored contiguously in memory, you can move a pointer forward or backward through an array by adding or subtracting integers. The pointer automatically steps by the **size of its type** - not by raw bytes.

```cpp
int scores[5] = {85, 92, 78, 90, 88};
int* ptr = scores;           // points to scores[0]

std::cout << *ptr << std::endl;        // 85
std::cout << *(ptr + 1) << std::endl;  // 92 - moves forward by 1 int (4 bytes)
std::cout << *(ptr + 2) << std::endl;  // 78 - moves forward by 2 ints (8 bytes)

ptr++;     // advance the pointer itself
std::cout << *ptr << std::endl;        // 92 - ptr now points to scores[1]
```

> [!IMPORTANT]
> When you write `ptr + 1`, C++ does not literally add 1 to the address. It adds `1 * sizeof(int)` - which is 4 bytes on most systems. For a `double*`, `ptr + 1` would advance by 8 bytes. The compiler handles the correct byte offset automatically based on the pointer's declared type.

## Traversing an Array with Pointer Arithmetic

```cpp
int scores[5] = {85, 92, 78, 90, 88};
int* ptr = scores;

for (int i = 0; i < 5; i++) {
    std::cout << *(ptr + i) << " ";
}

// Output: 85 92 78 90 88
```

This is exactly what `scores[i]` compiles down to - `*(scores + i)`. Array subscript notation is pointer arithmetic in disguise.

## Pointer Subtraction
Subtracting two pointers of the same type gives the **number of elements** between them (not the byte difference).

```cpp
int scores[5] = {85, 92, 78, 90, 88};
int* start = &scores[0];
int* end = &scores[4];

std::cout << (end - start) << std::endl;     // 4 - number of elements between them
```

> [!WARNING]
> Pointer arithmetic is only well-defined within the bounds of the same array (or one past the last element). Doing arithmetic between pointers from different arrays or unrelated variables is **undefined behavior**.

> [!NOTE]
> The type of a pointer difference is `std::ptrdiff_t`, a **signed** integer type from `<cstddef>` (8 bytes on a 64-bit system). Pointers into the same array can also be compared with `==`, `!=`, `<`, `>`, `<=`, and `>=`:
> ```cpp
> std::cout << (start < end) << "\n";      // 1 (start comes earlier in the array)
> std::cout << (start == end) << "\n";     // 0
> ```

## Void Pointers
A `void*` pointer can hold the address of any data type but cannot be directly dereferenced without casting first.

```cpp
int x = 42;
void* ptr = &x;

// Must cast before dereferencing
std::cout << *static_cast<int*>(ptr) << std::endl;    // 42
```

> [!NOTE]
> `void*` is primarily used in low-level memory management functions (`malloc`, `memcpy`) and generic C-style APIs. In modern C++, templates are the preferred way to write type-generic code instead.

## Pointers and C-Strings
A C-string (4.5) is an array of `char` ending in `'\0'`, so a `char` pointer is the natural way to refer to one. A `const char*` pointing at a string literal is the most common pointer type you will meet.

```cpp
const char* word = "Hello";
std::cout << word << "\n";                  // Hello
```

`std::cout` treats a `char*` as a **C-string** and prints characters until it finds `'\0'`, instead of printing an address. Walking a C-string with a pointer is the classic way to find its end:

```cpp
int length = 0;
for (const char* p = word; *p != '\0'; p++) {
    length++;
}
std::cout << length << "\n";                // 5 (this is what strlen does)
```

> [!WARNING]
> Because `std::cout` assumes a `char*` is a C-string, printing the address of a lone `char` goes wrong:
> ```cpp
> char c = 'A';
> std::cout << &c;                          // UNDEFINED BEHAVIOR: reads past c looking for '\0'
> std::cout << static_cast<void*>(&c);      // correct: prints the address, e.g. 0x7ffe48f6c837
> ```

## Arrays of Pointers vs Pointers to Arrays
Adding parentheses completely changes the meaning of a declaration.

### Array of Pointers

```cpp
const char* names[3] = {"Alice", "Bob", "Cara"};     // 3 pointers, each to a C-string

for (int i = 0; i < 3; i++) {
    std::cout << names[i] << " ";                         // Alice Bob Cara
}
std::cout << sizeof(names) << "\n";                       // 24 (3 pointers x 8 bytes)
std::cout << names[1][0] << " " << *names[2] << "\n";     // B C (first character of each string)

names[1] = "Bobby";                                  // re-point one element to another literal
```

This is exactly the shape of `char* argv[]` in `main` (4.5): an array of pointers, one per command-line argument. The parameter `char* argv[]` and `char** argv` mean the same thing, because the array decays to a pointer to its first element (a pointer to a `char*`).

### Pointer to an Array

```cpp
int matrix[2][3] = {{1, 2, 3}, {4, 5, 6}};

int(*rowPtr)[3] = matrix;             // a pointer to an array of 3 ints
std::cout << rowPtr[1][2] << "\n";          // 6
std::cout << sizeof(*rowPtr) << "\n";       // 12 (one whole row: 3 ints)
std::cout << sizeof(rowPtr) << "\n";        // 8  (it is still just a pointer)
// rowPtr + 1 moves forward by 12 bytes: one full row
```

This is the type a 2D array decays to when passed to a function (4.2).

| Declaration     | Meaning                                  | `sizeof` (64-bit) |
| --------------- | ---------------------------------------- | ----------------- |
| `int* p[3]`     | **Array** of 3 pointers to `int`         | 24                |
| `int (*p)[3]`   | **Pointer** to an array of 3 `int`s      | 8                 |

> [!TIP]
> Read a declaration from the name outward: `p` is... (inside the parentheses first) ...a pointer (`*`) to... an array of 3 (`[3]`) ...`int`. Without the parentheses, `[3]` binds tighter than `*`, so `int* p[3]` is an array of pointers.
