## Overview
Arrays store many values of the **same** type. This file covers three tools for modeling data more meaningfully:
* **`struct`** - groups values of *different* types into one named record.
* **`enum class`** - gives names to a fixed set of choices instead of magic numbers.
* **Type aliases** - give an existing type a more meaningful or shorter name.

## Structs

### Defining and Using a Struct

```cpp
struct Student {
    std::string name;
    int id;
    double gpa;
};                                     // the semicolon is REQUIRED

Student s1;                            // a variable of type Student
s1.name = "Alice";                     // access members with the dot operator
s1.id = 1;
s1.gpa = 3.8;
```

> [!WARNING]
> Forgetting the `;` after the closing brace is a classic error: `error: expected ';' after struct definition`.

The members are stored one after another in a single object, and each variable of the struct type has its **own** copy of every member.

### Initialization
Brace initialization fills the members **in declaration order**:

```cpp
struct Point {
    int x;
    int y;
};

Point p{3, 4};                         // x = 3, y = 4
Point q{1};                            // x = 1, y = 0 (members you leave out become zero)
Point z{};                             // x = 0, y = 0
Point u;                               // x and y are uninitialized (garbage) - same danger as in 2.2
Point d{ .x = 1, .y = 2 };             // designated initializers (C++20): name the members;
                                       // they must appear in declaration order
```

> [!NOTE]
> Brace initialization rejects narrowing, just like for plain variables (2.7): `Point bad{3.5, 4};` is an error (`narrowing conversion of '3.5e+0' from 'double' to 'int'`).

### Default Member Values
Give members a default so a struct is never left half-initialized:

```cpp
struct Student {
    std::string name;
    int id = 0;
    double gpa = 0.0;
};

Student s{"Alice", 1};                 // gpa keeps its default value: 0.0
```

### Copying and Comparing
Unlike arrays (4.1), a struct can be copied and assigned with `=`, and the copy is **independent**:

```cpp
Point p{3, 4};
Point r = p;                           // copies every member
r.x = 10;
std::cout << p.x << " " << r.x << "\n";     // 3 10
```

```cpp
Point a{1, 2}, b{1, 2};
// if (a == b) { }                     // ERROR: Point has no equality operator
if (a.x == b.x && a.y == b.y) { }      // compare member by member
```

> [!NOTE]
> Structs do not get `==` automatically. You can add it yourself later through operator overloading (Topic 6).

### Structs and Functions
All the parameter-passing rules from 3.2 apply:

```cpp
void print(const Student& s) {                  // read-only, no copy
    std::cout << s.name << " #" << s.id << " gpa " << s.gpa << "\n";
}

void promote(Student& s) {                      // modifies the caller's struct
    s.id += 100;
}

Point midpoint(const Point& a, const Point& b) {
    return { (a.x + b.x) / 2, (a.y + b.y) / 2 };    // return a struct to return several values
}

Point m = midpoint(Point{3, 4}, Point{10, 4});      // m is {6, 4}
```

> [!TIP]
> Returning a `struct` is the cleanest way to return several values from a function (see the TIP in 3.2). With a pointer to a struct, members are reached with `->` (shorthand for `(*ptr).member`), which is covered with pointers in Topic 5.

### Arrays of Structs and Nested Structs

```cpp
Student roster[3] = {
    {"Alice", 1, 3.8},
    {"Bob",   2, 3.2},
    {"Cara",  3, 3.9}
};

int bestIndex = 0;
for (int i = 1; i < 3; i++) {
    if (roster[i].gpa > roster[bestIndex].gpa) {
        bestIndex = i;
    }
}
std::cout << roster[bestIndex].name << "\n";        // Cara

for (const Student& s : roster) {              // range-based for works too
    std::cout << s.name << " ";
}
```

```cpp
struct Rectangle {
    Point topLeft;                             // a struct can contain other structs
    Point bottomRight;
};

Rectangle rect{{0, 10}, {10, 0}};
std::cout << rect.bottomRight.x << "\n";            // 10
```

### Struct Size and Padding (Preview)
`sizeof` a struct is often **larger** than the sum of its members, because the compiler inserts **padding** bytes so every member sits at an address suitable for its type:

```cpp
struct Padded    { char a; int b; char c; };       // sizeof = 12
struct Reordered { int b; char a; char c; };       // sizeof = 8
```

Same members, different order, different size. Ordering members from largest to smallest usually minimizes padding.

> [!NOTE]
> These sizes are typical for x86-64 (where `int` must start at a multiple of 4). Alignment and padding are covered in depth in the advanced memory material.

> [!NOTE]
> In C++ a `struct` can also hold member functions and constructors, and its only difference from a `class` is that members are `public` by default instead of `private`. That is covered in Topic 6. For now, treat a struct as a **plain bundle of data**.

## Enumerations
Magic numbers make code unreadable (see 2.6):

```cpp
int status = 2;                        // what does 2 mean?
```

An **enumeration** defines a type whose values are a fixed set of named constants.

### Scoped Enums: `enum class` (C++11, Preferred)

```cpp
enum class Color { Red, Green, Blue };     // Red = 0, Green = 1, Blue = 2

Color c = Color::Green;                    // names must be qualified: Color::Green
if (c == Color::Green) { }

int n = static_cast<int>(c);               // 1 - converting to int must be explicit (see 2.7)
```

An `enum class` is a **distinct type**: it never converts to or from `int` on its own:

```cpp
int bad = Color::Red;                  // ERROR: cannot convert 'Color' to 'int'
Color c2 = 1;                          // ERROR: cannot convert 'int' to 'Color'
std::cout << Color::Red;                    // ERROR: no match for 'operator<<' - cast to int first
```

Explicit values and the underlying type:

```cpp
enum class Status : unsigned char {    // underlying type: 1 byte instead of the default int
    Idle = 1,
    Running = 5,
    Stopped                            // continues from the previous value: 6
};
```

### Using an Enum with `switch`

```cpp
std::string describe(Color c) {
    switch (c) {
        case Color::Red:   return "red";
        case Color::Green: return "green";
        case Color::Blue:  return "blue";
    }
    return "unknown";                  // reached only if c holds an invalid value
}
```

> [!TIP]
> Leave out `default:` in a `switch` over an enum. If you later add an enumerator and forget to handle it, the compiler warns you: `enumeration value 'Blue' not handled in switch [-Wswitch]` (enabled by `-Wall`). A `default:` branch would silence that warning.

### Unscoped Enums (Legacy)

```cpp
enum Legacy { Cyan, Magenta };         // names leak into the surrounding scope

Legacy l = Magenta;                    // no qualification needed
int sum = l + 1;                       // implicitly converts to int: sum is 2
```

| Aspect                   | `enum class` (scoped)   | `enum` (unscoped)                         |
| ------------------------ | ----------------------- | ----------------------------------------- |
| Access to names          | `Color::Red`            | `Red` (pollutes the enclosing scope)      |
| Conversion to `int`      | Explicit cast only      | Implicit                                  |
| Name collisions          | Not possible            | Two enums in one scope can't share a name |
| Underlying type          | `int` by default, selectable | Implementation-chosen unless specified |

> [!NOTE]
> Prefer `enum class` in all new code. You will still meet unscoped enums in older code and in C libraries.

## Type Aliases
An **alias** gives an existing type another name:

```cpp
using Score = int;
using ull = unsigned long long;

Score best = 90;
ull big = 18000000000000000000ULL;

typedef unsigned long long ull2;       // legacy syntax, same effect
```

* An alias does **not** create a new type. `Score` and `int` are completely interchangeable, so aliases add readability but no type safety.
* Use them to shorten long type names, to document meaning (`using Meters = double;`), and to change a type in a single place.
* Prefer `using` over `typedef`: it reads left to right like an assignment, and unlike `typedef` it also works with templates (Topic 10).

> [!NOTE]
> `std::size_t` (2.2) is itself an alias for an unsigned integer type provided by the standard library.
