## Overview
Understanding how arrays actually exist in memory - and their deep, intentional relationship with pointers - is one of the most important conceptual leaps in C++. This is the gateway to understanding pointer arithmetic, dynamic memory, and how the language really works under the hood.

## How Arrays Are Stored in Memory
An array is a block of **contiguous memory** - every element sits immediately next to the previous one, with no gaps, in the exact order declared.

```cpp
int scores[5] = {85, 92, 78, 90, 88};
```

```
Memory        Addresses (example, 4 bytes per int)
Address:      1000     1004     1008     1012     1016
Value:        85       92       78       90       88
Index:        [0]      [1]      [2]      [3]      [4]
```

> [!NOTE]
>Because each `int` is 4 bytes, each subsequent element's address increases by exactly 4. This is the mathematical basis for how indexing actually works internally: `scores[i]` is computed as `*(scores + i)` - the base address plus an offset of `i * sizeof(int)`.

## 2D Array Memory Layout
A 2D array is **not** a true grid in memory - it's still one contiguous block, laid out row by row. This is called **row-major order**.

```cpp
int matrix[2][3]  = {
    {1, 2, 3},
    {4, 5, 6}
};
```

```
Actual memory layout (contiguous, row-major):
1 2 3 4 5 6
```

> [!IMPORTANT]
>"Row-major order" means the entire first row is stored before the second row begins. This matters for performance: looping with the **rightmost index changing fastest** (column inside row) accesses memory sequentially and is cache-friendly. Looping column-first jumps around memory and is significantly slower for large matrices.

```cpp
// Cache-friendly (row-major traversal)
for (int row = 0; row < 2; row++) {
    for (int col = 0; col < 3; col++) {
        std::cout << matrix[row][col];
    }
}

// Cache-unfriendly (column-major traversal on a row-major array)
for (int col  = 0; col < 3; col++) {
    for (int row = 0; row < 2; row++) {
        std::cout << matrix[row][col];
    }
}
```

## Array Names Decay to Pointers
This is one of the most important - and confusing - facts in C++: **the name of an array, in most expressions, automatically "decays" into a pointer to its first element.**

```cpp
int scores[5] = {85, 92, 78, 90, 88};

std::cout << scores << std::endl;         // prints a memory address
std::cout << &scores[0] << std::endl;     // prints the SAME memory address
std::cout << *scores << std::endl;        // dereferencing -> 85 (the first element)
```

> [!NOTE]
>`scores` and `&scores[0]` are functionally the same address. The array name is not a pointer, but in nearly every expression it decays into a pointer to its first element.

## Pointer Arithmetic on Arrays
Since the array name behaves as a pointer, you can navigate it using pointer arithmetic instead of indexing.

```cpp
int scores[5] = {85, 92, 78, 90, 88};
int* ptr = scores;         // ptr now points to scores[0]

std::cout << *ptr << std::endl;            // 85 (scores[0])
std::cout << *(ptr + 1) << std::endl;      // 92 (scores[1])
std::cout << *(ptr + 2) << std::endl;      // 78 (scores[2])

// These two lines are 100% equivalent:
std::cout << scores[2] << std::endl;
std::cout << *(scores + 2) << std::endl;
```

> [!TIP]
>`array[i]` is literally compiler shorthand for `*(array + i)`. Understanding this equivalence demystifies a huge portion of C-style pointer code you'll encounter, especially in legacy codebases and low-level libraries.

## Arrays vs Pointers  - Where They Differ
Despite the close relationship, arrays and pointers are **not the same thing**, and conflating them causes real bugs.

| Aspect              | Array                                                   | Pointer                                                 |
| ------------------- | ------------------------------------------------------- | ------------------------------------------------------- |
| Memory allocation   | Allocates actual storage for elements                   | Only stores an address (4 or 8 bytes)                  |
| `sizeof()` behavior | Returns total array size in bytes                       | Returns only the pointer's own size (8 bytes on 64-bit) |
| Can be reassigned?  | No - the array always refers to its own memory          | Yes - a pointer can be redirected to point elsewhere    |
| Lifetime            | Ties to its scope (stack) or explicit allocation (heap) | Independent of what it points to                        |

```cpp
int scores[5] = {85, 92, 78, 90, 88};
int* ptr = scores;

std::cout << sizeof(scores) << std::endl;      // 20 (5 ints * 4 bytes)
std::cout << sizeof(ptr) << std::endl;         // 8 (just a pointer, on 64-bit systems)
```

> [!WARNING]
>This is a classic trap: `sizeof(array) / size of (array[0])` works perfectly inside the *same scope* as the declaration, but the moment that array is **passed into a function**, it decays into a plain pointer - and `sizeof` inside that function returns the pointer's size (8), not the array's, silently breaking the size calculation.

```cpp
void printSize(int arr[]) {
    std::cout << sizeof(arr) << std::endl;     // 8, NOT 20 - arr has decayed to a pointer!
}

int main() {
    int scores[5] = {85, 92, 78, 90, 88};
    std::cout << sizeof(scores) << std::endl;       // 20, correct here
    printSize(scores);                    // but wrong once passed to a function
    return 0;
}
```

> [!NOTE]
> In a parameter list, `int arr[]` and even `int arr[5]` mean exactly `int* arr`. The `5` is ignored, so the function accepts arrays of **any** length with no error.
> ```cpp
> void viaBrackets(int arr[5]);          // identical to: void viaBrackets(int* arr);
> ```

>[!WARNING]
>Because of decay, a function can never know an array's size on its own - you must **always pass the size explicitly** as a separate parameter alongside the array pointer.

```cpp
void printArray(int arr[], int size) {
    for (int i = 0; i < size; i++) {
        std::cout << arr[i] << " ";
    }
}

int main() {
    int scores[5] = {85, 92, 78, 90, 88};
    printArray(scores, 5);      // size passed explicitly
    return 0;
}
```

## Keeping the Size: Reference to an Array
A **reference to an array** does not decay, so the size travels with the type:

```cpp
void viaRef(int(&arr)[5]) {
    std::cout << sizeof(arr) << " ";                        // 20 (the real array size)
    std::cout << sizeof(arr) / sizeof(arr[0]) << "\n";      // 5
}

int five[5] = {1, 2, 3, 4, 5};
int four[4] = {1, 2, 3, 4};

viaRef(five);
// viaRef(four);    // ERROR: array size must match
```

The parentheses in `int (&arr)[5]` are required: they say "arr is a reference to an array of 5 ints", not "an array of 5 references".

> [!NOTE]
> This version only works for one exact size. Letting the compiler deduce the size for any array uses templates (Topic 10), and `std::array` / `std::vector` (4.6) remove the problem altogether.
