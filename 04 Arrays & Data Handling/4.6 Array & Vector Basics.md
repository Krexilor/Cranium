## Overview
Raw arrays have real limitations (see "Limitations of Raw Arrays" in 4.1). The standard library offers two replacements that behave like proper values:

| Type                | Size                             | Storage         | Use when                                        |
| ------------------- | -------------------------------- | --------------- | ----------------------------------------------- |
| `T[N]` (raw array)  | Fixed, compile time              | Stack           | Learning, low-level code, C interop             |
| `std::array<T, N>`  | Fixed, compile time              | Stack           | Small collections whose size never changes      |
| `std::vector<T>`    | **Dynamic**, changes at runtime  | Heap (automatic)| **The default choice** for a sequence of items  |

> [!NOTE]
> This file is a practical introduction so you can use these types from now on. The full STL treatment (iterators, algorithms, other containers) comes later.

## `std::array`
A fixed-size array that knows its own size and behaves like a normal value:

```cpp
#include <std::array>

std::array<int, 4> a = {1, 2, 3, 4};        // array<element type, number of elements>
std::array<int, 4> b = a;                   // copying with = works
b[0] = 99;

std::cout << a.size() << "\n";              // 4
std::cout << a[0] << " " << b[0] << "\n";   // 1 99  (independent copies)
std::cout << (a == b) << "\n";              // 0: == compares the ELEMENTS
std::cout << sizeof(a) << "\n";             // 16: exactly the same size as int[4], no overhead

a.fill(7);                             // every element becomes 7

std::array c{5, 6, 7};                      // C++17: the type is deduced as array<int, 3>
std::cout << c.front() << c.back() << " " << c.at(2) << "\n";     // 57 7
```

* `[]` does **no** bounds checking (undefined behavior if the index is invalid), while `at()` checks the index and throws `std::out_of_range`:
  ```text
  what():  array::at: __n (which is 5) >= _Nm (which is 3)
  ```
* It works with range-based `for`, `size(a)`, and everything else you learned for raw arrays.

### Passing a `std::array`

```cpp
void show(const std::array<int, 4>& a) {
    for (int x : a) {
        std::cout << x << " ";
    }
    std::cout << "\n";
}

show(a);                               // OK
```

No decay happens, so the size is never lost. The size is **part of the type**, though: `std::array<int, 3>` and `std::array<int, 4>` are different types.

```cpp
std::array<int, 3> small{1, 2, 3};
// show(small);                        // ERROR: array extent must match
```

> [!NOTE]
> Writing a function that accepts an `array` of *any* size uses templates (Topic 10).

## `std::vector`
A **dynamic array**: it can grow and shrink at runtime, and it manages its own heap memory (no `new` / `delete` needed, which removes a whole class of leaks from Topic 5).

### Creating a Vector
```cpp
#include <std::vector>

std::vector<int> empty;                     // 0 elements
std::vector<int> nums = {4, 5, 6};          // initializer list
std::vector<int> zeros(5);                  // 5 elements, all 0
std::vector<int> sevens(5, 7);              // 5 elements, all 7
std::vector scores{85, 92, 78};             // C++17: the type is deduced as vector<int>
```

> [!WARNING]
> **Parentheses vs braces:** `std::vector<int> v(5)` creates **five** zeros, but `std::vector<int> v{5}` creates **one** element with the value `5`. Braces always prefer the initializer-list meaning.

### Common Operations

```cpp
std::vector<int> v;
v.push_back(10);                       // add to the end: {10}
v.push_back(20);
v.push_back(30);                       // {10, 20, 30}

std::cout << v.size() << "\n";              // 3
std::cout << v[1] << "\n";                  // 20 (unchecked)
std::cout << v.at(1) << "\n";               // 20 (checked)
std::cout << v.front() << v.back() << "\n"; // 1030
std::cout << v.empty() << "\n";             // 0

v.pop_back();                          // remove the last element: {10, 20}
v.clear();                             // remove all elements: size is 0
```

| Operation                    | Meaning                                           |
| ---------------------------- | ------------------------------------------------- |
| `push_back(x)`               | Append an element                                 |
| `pop_back()`                 | Remove the last element                           |
| `size()` / `empty()`         | Number of elements / is it empty?                 |
| `[i]` / `at(i)`              | Unchecked / checked access                        |
| `front()` / `back()`         | First / last element                              |
| `clear()`                    | Remove all elements                               |
| `resize(n)`                  | Change the number of elements to `n`              |
| `insert(pos, x)` / `erase(pos)` | Insert / remove at a position (see below)      |

### Inserting and Erasing in the Middle

```cpp
std::vector<int> w = {4, 5, 6};
w.insert(w.begin() + 1, 99);           // {4, 99, 5, 6}
w.erase(w.begin());                    // {99, 5, 6}
```

The position is given as an **iterator**, a pointer-like object (iterators are covered in the STL topic, so for now use this pattern as written). Inserting or erasing anywhere but the end shifts all later elements, so it costs time proportional to the number of elements moved.

### Size vs Capacity
A vector keeps a **spare buffer** so most `push_back` calls need no allocation:

* **`size()`** - how many elements it currently holds.
* **`capacity()`** - how many it can hold before it must allocate a bigger block.

```cpp
std::vector<int> grow;
for (int i = 0; i < 17; i++) {
    grow.push_back(i);
}
// GCC 13 reallocated at sizes 1, 2, 3, 5, 9, 17: capacity went 1, 2, 4, 8, 16, 32
```

Capacity typically doubles, but the exact growth rule is up to the implementation.

```cpp
std::vector<int> res;
res.reserve(100);                      // allocate room for 100 elements up front
res.resize(3);                         // size 3 (three zeros), capacity still 100
```

`reserve(n)` avoids repeated reallocations when you know roughly how many elements are coming. `clear()` sets the size to 0 but keeps the capacity.

> [!WARNING]
> When a vector reallocates, it moves its elements to a new block and frees the old one. **Every pointer, reference, and iterator into the old elements becomes dangling** (the same danger as in 5.3):
> ```cpp
> std::vector<int> v{1, 2, 3};
> int* p = &v[0];
> for (int i = 0; i < 10; i++) {
>     v.push_back(i);                // may reallocate
> }
> std::cout << *p << "\n";                // UNDEFINED BEHAVIOR: p may point to freed memory
> ```
> Do not keep pointers or references to elements across anything that can grow the vector.

### Looping Over a Vector

```cpp
std::vector<int> nums{1, 2, 3};

for (std::size_t i = 0; i < nums.size(); i++) {     // size() returns an unsigned type
    std::cout << nums[i];                           // 123
}

for (int n : nums) { }                         // copy of each element
for (int& n : nums) { n *= 2; }                // modify in place
for (const auto& n : nums) { std::cout << n; }      // read-only, no copy
```

> [!WARNING]
> `for (int i = 0; i < v.size(); i++)` compiles, but mixes signed and unsigned. GCC reports `comparison of integer expressions of different signedness: 'int' and 'std::vector<int>::size_type'`. Use `std::size_t`, a range-based `for`, or `ssize(v)` (C++20).

### Copying and Comparing
A vector is a proper value: copying it copies **all the elements**, and `==` compares them.

```cpp
std::vector<int> w = {99, 5, 6};
std::vector<int> copy = w;                  // independent copy
copy[0] = -1;

std::cout << w[0] << " " << copy[0] << "\n";        // 99 -1
std::cout << (w == copy) << "\n";                   // 0
```

### Vectors and Functions

```cpp
double average(const std::vector<int>& v) {         // read-only: const reference
    if (v.empty()) { return 0.0; }
    int sum = 0;
    for (int x : v) { sum += x; }
    return static_cast<double>(sum) / static_cast<double>(v.size());
}

void addOne(std::vector<int>& v) {                  // modifies the caller's vector: non-const reference
    for (int& x : v) { x += 1; }
}

std::vector<int> evens(int n) {                     // returning by value is fine (see 3.2)
    std::vector<int> result;
    for (int i = 0; i < n; i++) {
        if (i % 2 == 0) { result.push_back(i); }
    }
    return result;
}
```

> [!IMPORTANT]
> A `std::vector` passed **by value** copies every element. Pass large containers by `const&` (read-only) or `&` (to modify), exactly like `std::string` in 3.2.

### Two-Dimensional Vectors

```cpp
std::vector<std::vector<int>> grid(3, std::vector<int>(4, 0));    // 3 rows x 4 columns, all zeros
grid[1][2] = 5;

std::cout << grid.size() << "\n";                       // 3 (rows)
std::cout << grid[0].size() << "\n";                    // 4 (columns)
std::cout << grid[1][2] << "\n";                        // 5
```

Because each row is a separate vector, row lengths can differ (a "jagged" array), and the rows are **not** stored in one contiguous block like `int[3][4]` (4.3). No fixed column count has to appear in function signatures, which makes them far easier to pass around than raw 2D arrays (4.2).

### Out-of-Range Access

```cpp
std::vector<int> v{1, 2, 3};
v.at(10);              // throws std::out_of_range
v[10];                 // undefined behavior: no check at all
```

An uncaught exception terminates the program (Topic 8 covers how to handle them). A **checked** crash is far easier to debug than the silent corruption `[]` can cause, so use `at()` while you are learning.

## Which One Should I Use?

| Situation                                                        | Choice                          |
| ---------------------------------------------------------------- | ------------------------------- |
| Number of elements is unknown or changes at runtime              | `std::vector`                   |
| Small, fixed-size collection (a 3D coordinate, 7 weekdays)       | `std::array`                    |
| Default when unsure                                              | `std::vector`                   |
| Interfacing with a C API, or learning how memory works           | Raw array                       |
| Fixed size AND you need to pass it around or copy it             | `std::array`, not a raw array   |

> [!TIP]
> A type alias (4.4) keeps long container types readable: `using Grid = std::vector<std::vector<int>>;`.

> [!NOTE]
> `std::vector` and `array` store their elements contiguously, just like raw arrays, so all the memory-layout and cache behavior from 4.3 still applies. You get safety and convenience without giving up speed.
